## 关键结论（后续复用）

- `AllGPTORG/VOSR_1.4B_Mobile` 的 `/onnx` 是 **FP16** 分级图；量化版是 `pi/w8a16`（MatMulNBits INT8，需 ORT ≥1.28，本机 1.22.1 CPU EP 报 “Only 4b quantization is supported”）、`sd8g3` 是骁龙 QNN EPContext，都不能在桌面 ONNX Runtime 用。
- 本机 Intel Arc 140T 驱动下 **连续创建第 3 个 DirectML 会话会原生崩溃**（`InferenceSession::Init` 0xC0000005），托管层无法捕获；VOSR 后端顺序定为 厂商 GPU(OpenVINO/TensorRT-RTX) → DirectML → CPU。
- 生成式超分的分块不能直接裁剪窗口内部（每 384 px 一条垂直亮暗带），必须重叠 + 余弦交叉淡化。
- `.qa/vosr/` 保留了九张图、harness 与 smoke 日志作为证据；`FfmpegSmokeTest --image-vosr <模型目录>` 是正式回归入口。

## 修复 VOSR 重复下载（同日追加）

- 现象：每次进入图像页都重下 VOSR 且永远装不完；用户目录里 dino 图缺失、`00_12` 只剩 `.partial`。
- **真正根因：`ModelManifest.Vosr` 里两张图的 SHA-256 手抄错了一个字符**（dino 写成 `…8ECAEEA07F…`、`00_12` 写成 `…A7DE1E1BFB…`）。下载内容其实完全正确，校验必然失败 → 删成品重下。取证：让下载器保留"坏包"，与 curl 直连的正常文件逐字节比较一致，仅期望哈希不同；HF API 的 LFS sha256 与字节一致。
- 次要缺陷：无断点续传、15 min 整体超时、失败即删 `.partial`、恢复页面即触发下载、每次全量哈希 3.3 GB、校验器把 IO 占用当内容不符（`File.OpenRead` 抛异常被吞成 false）。
- 修复：哈希改正并用九图字节+HF API 复核；Range 续传（独占打开片段取偏移、200 回退整下、416/内容不符清片段重下一次）；90 s 空闲超时；校验器 `FileShare.ReadWrite|Delete` + 重试 3 次 + 结果缓存；`RestoreState` 期间不自动下载；`EnsureModelAsync` 单飞。
- 回归：`FfmpegSmokeTest --model-resume` 13 项、`--image-models-only`、`--model-live`（真实网络单条目）、`--http-range`（续传拼接完整性）。用户目录九图 SHA 全部通过，VOSR 实际推理 43.0 s / 15 块。
- 环境提醒：本机 `C://Program Files\dotnet\sdk\10.0.*` 的 `dotnet.dll` 缺失（用户在更新 VS），期间临时把 global.json 指向 11.0.100，收尾已用 `git checkout` 还原。
