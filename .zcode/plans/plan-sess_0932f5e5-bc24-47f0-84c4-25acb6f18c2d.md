## 修复切到 WebM 后 codec 不匹配（MKV+VP8 → WebM 显示 AV1 SVT）

### 真正的根因（通过复现确认）

控制台复现输出：
```
MKV+VP8+Vorbis: V=4 (VP8 in MKV list), A=3 (Vorbis)
-> WebM:
  V=3, A=2    ← 但 WebM 列表是 [VP8, VP9, AV1(aom), AV1(SVT)] 和 [Opus, Vorbis, None]
                 期望：V=0 (VP8), A=1 (Vorbis)
                 实际：V=3 (AV1 SVT), A=2 (None)
```

**根因**：现有 `ClampCodecIndicesForCurrentContainer` 只做 `Math.Clamp(index, 0, Count-1)`——**保留数值大小**，不识别"该 index 在新列表里其实对应了别的 codec"。MKV 列表里 index 4 = VP8，但 WebM 列表只有 4 项（index 4 越界），clamp 到 3 = AV1(SVT)。同样 MKV Vorbis(3) → WebM (length 3) clamp 到 2 = None。

**用户主观感受**：在 MKV 选了 VP8，切到 WebM 后下拉框显示 AV1(SVT)，看起来"VP8 消失了 / 选择变成空（语义上）"。这就是用户报告的"修复未生效"。

### 修复思路

把"按 index 算"改成"按 enum 翻译"——切容器前先把旧 index 翻译成 `VideoCodec` / `AudioCodec` enum，再在新容器的过滤列表里**按 codec 名称重新定位**，找不到才 fallback 到 0。

### 改动文件

仅 `FancyTool/ViewModels/VideoTranscodeViewModel.cs`。

#### 改动 1：在 `ContainerIndex` setter 里捕获"旧 enum"

93-110 行改成：

```csharp
public int ContainerIndex
{
    get => field;
    set
    {
        var oldContainer = field;
        if (SetProperty(ref field, value))
        {
            // Translate the previous codec/audio indices to enums BEFORE
            // the new FilteredVideoCodecs/AudioCodecs lists take effect,
            // then locate the same codec/audio in the new container's
            // allowed list. This preserves the user's actual codec choice
            // across container switches (e.g. MKV+VP8 -> WebM still shows VP8).

            OnPropertyChanged(nameof(ShowTwoPass));

} = 0;
```

#### 改动 2：新增 `RealignCodecIndicesToCurrentContainer`

替换原 `ClampCodecIndicesForCurrentContainer`（143-153 行附近），新函数做"按 enum 翻译 + 找不到 fallback"：

```csharp
/// <summary>
/// Realign VideoCodecIndex / AudioCodecIndex to the current container's
/// filtered lists by translating the previously selected codec to an enum
/// and locating the same codec in the new list. Falls back to 0 when the
/// codec is not present in the new container (or the index was already
/// out of range). This preserves the user's actual codec choice across
/// container switches instead of just clamping the numeric index, which
/// was previously mapping e.g. MKV+VP8 (index 4) to WebM+AV1(SVT) (index 3).
/// </summary>
public void RealignCodecIndicesToCurrentContainer(VideoContainer oldContainer)
{
    var oldVideoLabels = FilterVideoCodecsForContainer(oldContainer);
    VideoCodec? desiredVideo = null;
    if (VideoCodecIndex >= 0 && VideoCodecIndex < oldVideoLabels.Count)
    {
        desiredVideo = MapLabelToVideoCodec(oldVideoLabels[VideoCodecIndex]);
    }

    var oldAudioLabels = FilterAudioCodecsForContainer(oldContainer);
    AudioCodec? desiredAudio = null;
    if (AudioCodecIndex >= 0 && AudioCodecIndex < oldAudioLabels.Count)
    {
        desiredAudio = MapLabelToAudioCodec(oldAudioLabels[AudioCodecIndex]);
    }

    var video = FilteredVideoCodecs;
    var audio = FilteredAudioCodecs;

    int newVideoIndex = 0;
    if (desiredVideo is VideoCodec v && v != VideoCodec.Gif)
    {
        string targetLabel = VideoCodecToLabel(v);
        int found = video.IndexOf(targetLabel);
        if (found >= 0) newVideoIndex = found;
    }
    else if (video.Count > 0)
    {
        newVideoIndex = 0;
    }

    int newAudioIndex = 0;
    if (desiredAudio is AudioCodec a && a != AudioCodec.None)
    {
        string targetLabel = AudioCodecToLabel(a);
        int found = audio.IndexOf(targetLabel);
        if (found >= 0) newAudioIndex = found;
    }
    else if (audio.Count > 0)
    {
        newAudioIndex = 0;
    }

    // Force notifications regardless of whether the numeric value changed,
    // because Avalonia's ComboBox SelectedIndex binding can otherwise retain
    // a stale display when ItemsSource changes underneath it.
    bool videoChanged = SetProperty(ref _videoCodecIndexField, newVideoIndex);
    bool audioChanged = SetProperty(ref _audioCodecIndexField, newAudioIndex);
    if (videoChanged) ResetPresetToCustom();
    if (audioChanged) ResetPresetToCustom();

    OnPropertyChanged(nameof(FilteredVideoCodecs));
    OnPropertyChanged(nameof(FilteredAudioCodecs));
}
```

> **字段问题**：`field` 关键字在 C# 13 中是上下文关键字，在 lambda / 不同方法里无法捕获。我会把 `VideoCodecIndex` / `AudioCodecIndex` 显式改写为 backing field + 普通 property（去掉 `field` 关键字），或者保留 `field` 关键字并直接用属性 set 方法赋值。后者更安全——见下方"实现细节"。

### 行为对照

| 场景 | 修改前 | 修改后 |
|---|---|---|
| MKV+VP8(4) → WebM | V=3（AV1 SVT，错的） | V=0（VP8，按 enum 翻译） |
| MKV+Vorbis(3) → WebM | A=2（None，错的） | A=1（Vorbis） |
| MKV+VP9 → Avi（无 VP9） | V=1（H.264，按位置 clamp） | V=0（H.264，按 enum fallback） |
| MKV+VP8 → MP4（VP8 在 MP4 列表里） | V=5（VP9，错位） | V=4（VP8，正确） |
| 状态恢复 MKV+VP9 → 启动（列表已变） | 不可预测 | 按 enum 在新列表里找，找不到 fallback |
| VideoCodecIndex=5 直接写入 | PropertyChanged 不发（值未变） | 强制发 PropertyChanged |

### 风险

- 改动局限在 `VideoTranscodeViewModel.cs` 单文件。
- `field` 关键字 + `partial` 类：在同一个文件里仍可读 `field`，但**多个方法访问 field 需要明确 backing field 名**。我会把 `VideoCodecIndex` / `AudioCodecIndex` 改成显式 backing field（`_videoCodecIndex` 等），确保 `RealignCodecIndicesToCurrentContainer` 通过 setter 修改时也能正常触发属性通知。
- `MapFilteredVideoCodec` / `MapFilteredAudioCodec` 公开方法签名不变（参数仍是 `(container, index)`），`BuildOptions` 调用方零改动。
- 不改枚举、不改 UI XAML、不改 ffmpeg 命令行参数。
- 回滚：单文件 revert。

### 实现细节（关于 `field` 关键字）

由于 C# 13 的 `field` 上下文关键字只在声明属性的同一个 setter 里有效，跨方法读写 field 不可行。新方案：

```csharp
private int _videoCodecIndexField;
public int VideoCodecIndex
{
    get => _videoCodecIndexField;
    set { ... _videoCodecIndexField = clamped; ... }
}
```

这样 `RealignCodecIndicesToCurrentContainer` 可以直接读写 `_videoCodecIndexField` / `_audioCodecIndexField`，或者**通过属性 setter 间接写**——后者更简洁，setter 已经会触发 PropertyChanged。
