# 视频转码·拼接模式实现计划

## Context

视频转码页目前是 `Parallel.ForEachAsync` 逐文件独立转码（各自输出）。需求：新增"拼接模式"勾选框，勾选后把列表中所有视频**按列表顺序拼成一个文件**；列表支持**拖拽排序**；每个片段有独立的**循环次数**（该片段在成片中重复出现 N 次）。

已确认的决策：
- 分辨率不一致时：以**第一个视频为基准**，其余片段按比例缩放后**居中加黑边**（letterbox）；帧率保留各段原始时间戳（输出 VFR）。
- 排序交互：**手写拖拽排序**（Avalonia ListBox 无内置支持，约 200 行设施代码）。

技术路线（关键决策）：**单遍多段解码、一次编码**——顺序解码各片段（×循环次数），逐帧归一化到基准参数后喂入同一个滤镜图 + 编码器 + 封装器。不采用"先逐段转中间文件再 concat remux"方案（双倍磁盘、concat demuxer 对流参数一致性要求苛刻、失败模式隐蔽）。此路线对异构输入（不同分辨率/编码/帧率/音频格式）天然兼容，且完全不改动现有 `ConvertOnce` 热路径（回归风险隔离到新分部文件）。

## 服务层

### 1. `Models/VideoModels.cs`
- 新增 `public sealed record VideoConcatSegment(string FilePath, int LoopCount, double TrimStartSeconds, double? TrimEndSeconds)`。
- `VideoFileItem` 加 `int LoopCount { get; set; } = 1`（setter 钳位 1..99，UI NumericUpDown 同步钳位）。

### 2. `Services/IVideoTranscodeService.cs` + 新分部 `Services/VideoTranscodeService.Concat.cs`
新方法（签名镜像 `TranscodeAsync`，见 `IVideoTranscodeService.cs:30`）：
```csharp
Task ConcatTranscodeAsync(IReadOnlyList<VideoConcatSegment> segments, string outputPath,
    VideoTranscodeOptions options, IProgress<double>? progress = null, CancellationToken ct = default,
    IProgress<VideoPreviewFrame>? preview = null, IProgress<VideoEncodingProgress>? statistics = null);
```

`VideoTranscodeService.Concat.cs` 实现要点（partial 类直接复用现有 private static 辅助）：
- 前置：`FFmpegNative.TryLoad` → 逐段 `ProbeInternal`（无视频流的段报含文件名的错误）；每段 `ValidateTrim`；循环数钳 1..99。`totalSec = Σ 各段有效时长(裁剪后)×LoopCount`。
- 结构镜像 `TranscodeAsync`（`VideoTranscodeService.cs:145`）：tmp 文件（`BuildTmpPath`）→ 两通循环（`ScaledProgress` 分段）→ 成功原子 Move / 失败 `TryDelete`。
- **基准段 = segments[0]**：打开其输入 + 软件解码器（v1 拼接不走 NVDEC，硬件**编码**不受影响），据此建共享滤镜图（`CreateBufferSource` 带覆写参数、`BuildFilterDescription`、`BindGraphAndConfigure`）、`ConfigureVideoEncoder(sink link)`、`ResolveOutputColor`；音频仅在基准段有音轨且 `AudioCodec != None && Container != Gif` 时经 `SetupAudioEncoder` 建共享音频编码器 + 共享 `EncoderFrameFeeder`。
- **逐段 × 逐循环迭代**：每轮重新打开该段的 demux + 解码器（循环=重新解码，实现最简且正确）；每段独立 `TrimTimeline`（复用 `VideoTranscodeService.Trim.cs:18`，裁剪+时间轴重置）；视频帧 `KeepVideo` 后把本地秒数换算成**基准 timebase 下的全局 pts**（累计偏移），参数（w/h/pixFmt）与基准不一致时经 `sws_scale` 归一——letterbox：保持源 DAR 缩放至基准画布内接居中，底图填黑；音频帧 `KeepAudio` + 段内独立 `SwrContext`（目标=共享音频编码器参数）→ `ConvertAudioFrame`。送帧后复用 `DrainSinkInto`，全局进度 `(全局已完成秒 + 段内秒)/totalSec`。
- 冲洗/清理镜像 `ConvertOnce` 的 flush 与 finally-Release 块（幂等清理）。
- 对 `VideoTranscodeService.cs` 仅有**一处增量改动**：`EncoderFrameFeeder` 加一个偏移小方法（如 `AddStartSamples(long)`）用于把音频定位到全局时间轴；其余一概不动。

v1 限制（ADR 中记录）：拼接模式下 AI 超分、插帧不可用（其管线从单一输入派生）；混合 HDR/SDR 段以第一段色彩决策为准；某段无音轨则该段区间静音。

## ViewModel（`ViewModels/VideoTranscodeViewModel.cs`）

- `IsConcatMode`（`[ObservableProperty]`，setter → `InvalidateAllCommands()`）；拼接时 `BuildOptions()` 强制 `SuperResolutionEnabled=false`、`InterpolationMode=None`（UI 侧同时禁用两组控件）。
- `StartTranscode`（L1302）分支：`IsConcatMode` → 串行拼接路径。输出路径 = `OutputPathPlanner.PlanUniquePath(outputDir, 首段文件名 + "_merged", 扩展名, useSourceDir, taken)`；逐段：Post `item.Status/Progress`（选中跟随激活段）、段级 `EncodingStatisticsReporter` 与 `CreateProgressPreview(item)`；全局 `ConversionProgress` 按有效时长加权；段失败 → 中止（当前段 Failed + 消息，剩余段保持 Pending，tmp 由服务清理）、成功 → `Msg_ConcatDone`。暂停语义与现批处理一致（段间等待，进行中跑完）。
- `FileItems.Move` 由拖拽行为驱动（VM 只需暴露 `IsReorderEnabled => IsConcatMode && !IsBusy` 供行为绑定）。
