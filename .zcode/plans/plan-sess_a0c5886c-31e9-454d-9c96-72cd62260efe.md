# 视频转码新增流复制（stream copy）：编码器下拉加「Copy」选项

## Context

当前 `VideoTranscodeService.ConvertOnce` 是全解码→滤镜→重编码管线（`Services/VideoTranscodeService.cs:233`），换容器时即使源编码已兼容也必须整条重编码，耗时且有画质损失。需求：在视频/音频编码器下拉各加「直接复制（Copy）」选项，不重编码直接复制流（packet 直通），支持四种组合（视频 copy/重编码 × 音频 copy/重编码）。

已确认的行为语义：
- 选中 Copy 时禁用（不重置）互斥控件，`BuildOptions` 兜底忽略冲突参数；服务端入口再校验拒绝（防 API 直调）
- 拼接模式不支持 copy（列表排除 + 服务端拒绝）
- copy 支持时间段裁剪（trim）：视频从 ≥start 的**第一个关键帧**开始写（与 `ffmpeg -ss -c copy` 同语义），音频按 pts 窗口直通
- 批处理中源编码与目标容器不兼容的文件**失败并在明细报告**（用 `avformat_query_codec` 预检给出明确错误）

## 改动清单

### 1. 枚举 — `FancyTool/Models/VideoModels.cs`
- `VideoCodec` 末尾加 `Copy = 8`（在 `Mpeg4` 之后，保持 `Enum.GetValues` 与标签列表位置对应）；`AudioCodec` 末尾加 `Copy = 7`（`None=6` 丢弃语义不变）

### 2. ViewModel — `FancyTool/ViewModels/VideoTranscodeViewModel.cs`
- `FilterVideoCodecsForContainer` / `FilterAudioCodecsForContainer`（L210-228）改为实例方法：非 GIF、非 `IsConcatMode` 时在 MP4/MKV/MOV/AVI 各列表末尾追加 `"Copy"`；GIF 保持现状
- `MapVideoCodecByLabel` / `MapAudioCodecByLabel`（L1868-1891）加 `"Copy"` case
- 新属性 `IsVideoCopyMode` / `IsAudioCopyMode`（由 `SelectedVideoCodec`/`SelectedAudioCodec` 派生，setter 通知）；`ShowTwoPass`（L316）追加排除 videoCopy
- `IsConcatMode` 变化处（L333-344）追加 `OnPropertyChanged(FilteredVideoCodecs/FilteredAudioCodecs)` + `EnsureCodecSelectionValid()`（copy 自动回落，复用现有回落机制）
- `BuildOptions`（L1695-1761）：GIF 强制块后追加 copy 兜底——`vCodec==Copy` 时强制 `TwoPassEnabled=false、HardwareBackend=Software、ScaleMode=None、CropEnabled=false、FpsMode=SameAsSource、Deinterlace=None、Denoise=None、HdrOutput=SameAsSource、SuperResolutionEnabled=false、InterpolationMode=None`；`aCodec==Copy` 时 `AudioGainDb=0`（保留用户参数值，仅构造 options 时忽略）

### 3. View — `FancyTool/Views/VideoTranscodeView.axaml`
- 视频/音频编码下拉（L58/L73）下方各加一条 `IsVisible="{Binding IsVideoCopyMode/IsAudioCopyMode}"` 的 hint 文本（新 i18n 键）
- 画质 Tab（L94 Group_Quality）加 `IsEnabled="{Binding !IsVideoCopyMode}"`（禁用不隐藏，参数保留可见）
- 滤镜区（缩放/裁剪/FPS/去隔行/降噪，在编辑 Tab）与插帧区加 `IsEnabled="{Binding !IsVideoCopyMode}"`
- 超分/插帧区现有多条件：新增 VM 复合属性 `AiEnhancementsEnabled => !IsConcatMode && !IsVideoCopyMode` 替换 L138/L221 的 `!IsConcatMode` 绑定（Avalonia 绑定不支持 `&&`）
- 音频 Tab 内码率、音量增益两个 StackPanel 加 `IsEnabled="{Binding !IsAudioCopyMode}"`（IsEnabled 可嵌套继承，与外层 `!IsGifMode` 不冲突）

### 4. 服务端 — `FancyTool/Services/VideoTranscodeService.cs`
`ConvertOnce` 内加分支（不动整体结构）：
- 输入流发现后计算 `bool videoCopy / audioCopy`；入口校验冲突组合（滤镜/AI/HDR/两通/硬件/增益）→ 抛 `Msg_CopyConflictingOptions`
- `videoCopy`：跳过 NVDEC（L290）、解码器（L303）、色彩读取（L305-306）、编码器+滤镜图+编码器打开（L315-416 整段 `if (!videoCopy)`），else 建视频输出流：`avformat_new_stream` + `avcodec_parameters_copy(out->codecpar, vInStream->codecpar)`、`time_base` 取输入流；`avformat_query_codec(...)==0` 时抛 `Msg_CopyCodecUnsupported`
- `audioCopy`：跳过 `OpenAudioDecoderStream` 的 aDec 创建与 `SetupAudioEncoder`（L423-427），音频输出流同上参数拷贝 + 预检
- 新私有方法 `WriteCopiedPacket(pkt, inStream, outStream, startTs/endTs, 关键帧状态, progress, ct)`：窗口判断 → 视频首包等 `AV_PKT_FLAG_KEY` → pts/dts 平移减 startTs → `av_packet_rescale_ts(inTb→outTb)` → `stream_index` → `av_interleaved_write_frame` → 按 pts 报告时间进度
- 主循环（L474/488）视频/音频包各自 `copy ? WriteCopiedPacket : 现有解码链`；trim 的 seek 优化（L448-455）对 copy 同样生效；copy 不用 `TrimTimeline` 帧级状态，结束判断用自己的 bool
- `EncodingProgress` 构造（L460）copy 时用输入流帧率替代 `vEnc->framerate`；冲洗段（L509-534）`if (!videoCopy)` / `if (!audioCopy)` 跳过对应 flush；`metrics`、`previewConverter` 在 copy 时不启用
- `TranscodeAsync`（L145）：copy 强制单通
- 拼接入口 `ConcatTranscodeAsync`（`Services/Concat.cs:21`）：`VideoCodec==Copy || AudioCodec==Copy` → 抛 `Msg_CopyUnsupportedInConcat`

### 5. i18n — `zh-CN.json` + `en-US.json` 同步新增 4 键
`Hint_CopyMode`（copy 模式提示）、`Msg_CopyConflictingOptions`、`Msg_CopyCodecUnsupported`（含 {0} 编码名 {1} 容器名占位）、`Msg_CopyUnsupportedInConcat`。编码器标签 `"Copy"` 硬编码英文，与现有 "GIF"/"AAC"/"None" 一致。

### 6. 烟测 — `FancyTool/_tools/FfmpegSmokeTest/`
- 新文件 `CopyTests.cs`（仿 `ConcatTests.cs`）：先从 sample 转出 H.264+AAC 标准源，再跑：
  1. 双 copy → MP4 / → MKV（换容器）：Verify 输出编码与源相同、时长近似
  2. 视频 copy + 音频 Opus → MKV；视频 H.265 + 音频 copy → MP4（混合组合）
  3. copy + `WithTrim(1s, null)`：时长≈源-1s、首包关键帧
  4. 守卫：copy+缩放 → 预期抛冲突异常
  5. 不兼容：VP9 源 copy → AVI：预期 `Msg_CopyCodecUnsupported` 失败
- `Program.cs`：主流程加 `RunCopyCases`（与 `RunConcatCases` 并列），另加 `--copy-only` 独立入口

### 7. 文档
- 新 ADR `FancyTool/docs/adr/0019-video-stream-copy.md`（中文）：互斥矩阵、trim 关键帧语义、批处理失败语义、容器预检、拼接不支持

## 风险提示

- 枚举加值后 `Enum.GetValues` 顺序必须与 `AllVideoCodecLabels` 保持位置对应（Copy 加在两侧末尾）
- `MapVideoEncoderName` / `SetupAudioEncoder` 的 switch 不应收到 Copy（守卫拦截），仍加防御 default 抛异常
- copy 的负 dts 交给 muxer 默认 `avoid_negative_ts` 处理（MP4/MKV 均安全）
