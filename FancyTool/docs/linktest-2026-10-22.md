# 通信链路测试（TCP / UDP 带宽与 UDP 丢包率）— 2026-10-22

## 功能说明

TCP 调试页与 UDP 调试页新增「链路测试」独立模式（页面顶部功能切换）：

- **TCP 链路测试**：接收端监听、发送端按块大小持续发送指定时长；结束时发送端在流尾写入 16 字节结束标记，接收端据此区分「正常完成」与「对端中止」，两端各自输出平均带宽。默认 10 秒 / 64 KB 块，块大小 1 KB–4 MB。
- **UDP 链路测试**：发送端按序号发送 DATA 包（默认 1400 字节，避免 IP 分片），结束发 FIN（声明总数）并等待 FIN-ACK；接收端按魔数过滤无关流量、按序号计数，FIN 后再收 500 ms 尾巴包，把「收包数 / 字节 / 最大序号」回传发送端。**两端都能看到丢包率**（丢 = 发送总数 − 接收数）。默认目标速率 10 Mbps（0 = 不限速），时长 1–600 秒。
- 与通信调试互不干扰：链路测试使用专属 Socket 与独立服务（`TcpLinkTestService` / `UdpLinkTestService`），不经过 `TcpServerService` / `UdpService` 的事件与日志管线；共用页面的地址/端口输入，进入测试前自动停止当前通信。

## 协议（UDP 及 TCP 流尾标记）

```
DATA / FIN（16 字节头，小端）:
  [0..3]  Magic "FTLT"   [4..7] Flags(0=DATA,1=FIN,2=FIN-ACK)
  [8..15] DATA=序号(0起) / FIN=发送总包数
FIN-ACK（40 字节）: 头 + 接收包数(8) + 接收字节(8) + 最大序号(8)，重复发送 3 次提高送达率
```

要点：接收端只在收到 FIN 后才回传统计（中止时不回传，避免发送端消费过期快照）；UDP 丢包率以 FIN 声明的总数为准；TCP 靠流尾标记区分正常完成与中止（两者在 TCP 上都是 EOF）。重复/乱序包理论上会引入误差（发送端不重发，环回/局域网可忽略）。

## 验证

环境：Windows 11 26300（YFTN-PKC），.NET SDK 10.0.401，环回地址，2026-10-22。

```
dotnet run --project FancyTool/_tools/LinkTestSmokeTest
```

烟测走真实服务代码路径（`FancyTool/_tools/LinkTestSmokeTest`），17 项全部通过：

- TCP 环回 2 s/64 KB：两端字节完全一致（≈2.1 GB / ≈8.8 Gbps），快照事件正常。
- UDP 环回 3 s/1400 B/10 Mbps：发收 2681 包、0 丢包、实测 8.56 Mbps（限速 ±20% 内），FIN-ACK 统计回传成功，两端丢包数一致。
- TCP 发送端中途停止：两端均输出「已中止」汇总（含已传数据），接收端不误报正常完成。
- UDP 接收端先停：发送端正常结束并正确显示「未收到对端统计」。
- 等待对端期间停止（无任何数据）：必发空中止回执，界面不会停留在「测试中」。

原始输出与环境记录：`.qa/linktest-2026-10-22/`（smoke-output.txt、env.txt）。

## 已知限制

- 未做实机 GUI 操作验证（仅编译期 XAML 绑定校验 + 服务层真实路径烟测）；页面布局、深浅色主题与运行时语言切换需实机观察。
- 单流测试（TCP 一条连接、UDP 单播）；UDP 限速为软件令牌节流，实际速率受定时器粒度影响（约 ±20%）。
- 丢包率假设发送端每个序号只发一次（本工具协议即如此）；网络设备复制/乱序极端场景下计数有理论误差。
