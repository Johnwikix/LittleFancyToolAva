# 终端类调试页统一为多会话模型

日期：2026-11-27。

## 背景与约束

- 串口调试先做了多端口（见 `../serial-multi-port-ui-design.md`），TCP / UDP 仍是单会话页面。三页各自维护一份近 50 行的定时发送循环，计数合并、未读、HEX 日志格式化、`DispatcherTimer` 也是各一份。
- TCP / UDP 的会话身份来自文本框（模式 + 地址 + 端口），没有可以枚举的"可添加项"；显示名随输入变化。串口的端口名创建后不变。
- `UdpService` 给 socket 设了 `ReuseAddress=true`：两个会话绑定同一端口会成功，不报错，之后的数据报归属不确定。TCP 则由系统 bind 拒绝第二个监听。
- 链路测试是进程内单例服务，一次只能跑一个测试，"每会话一份"没有意义。
- 三个页面都是单例，导航离开不释放；关闭页面不等于会话结束。

设计与评审记录见 `../tcp-udp-multi-session-design.md`（v1.1）。

## 决策

1. **抽公共基类，三页派生。** 会话级 `TerminalSessionViewModelBase`（日志、计数、未读、计时、状态、发送选项、定时发送循环）、页面级 `TerminalPageViewModelBase<TSession>`（会话集合、当前会话、下拉项同步、关闭并选邻、合并日志、聚合文案、"全部会话"发送）、`SessionChoiceItem`，以及三页共用的节拍 `TerminalTicker`（16ms / 1s）。
2. **会话是状态与资源的单位。** 参数、日志、计数、发送内容、定时发送都归会话自己；页面一次只显示一路，切换只改变显示对象，其它会话的收发与定时发送不受影响。不设会话上限。日志分级：当前会话 20000 行，其余各 5000 行，合并日志 20000 行。
3. **定时发送是会话级的。** 每路一个任务和取消令牌，开始时在 UI 线程取发送目标快照（`CreatePollingSender()`），之后改界面不影响进行中的定时发送。
4. **服务实例由 Hub 创建。** `ISessionHub<T>` / `SessionHub<T>` 用工厂委托创建实例，不经根容器解析服务接口，关闭会话即释放；退出时 `Hub.Dispose` 逐个停止，单项失败不影响其它。
5. **新建入口是下拉末尾固定的"新建会话"项。** 默认复制当前会话并把端口 +1（串口仍是"添加端口 COMx"，按枚举结果列出）。创建推迟到 ComboBox 选中变更的绑定回写结束之后（同一帧内）：在回写中途改下拉集合会让控件重入并记错上一次选中项，下一次再选该项就不再通知。
6. **运行中冻结绑定身份。** TCP 冻结模式、地址、端口；UDP 冻结模式、本地地址、本地端口、组播地址。UDP 的远程地址 / 端口与组播端口只是发送目标，保持可改。替代了原来"运行中切模式即停止"的做法。
7. **端点冲突在应用层判定**（`BindEndpoint` + `EndpointConflict`，与服务层共用同一套地址解析）。TCP：服务端会话之间互斥，端口相同且地址相同或任一方是通配地址。UDP：普通会话与任何会话互斥，组播会话之间放行。判定与占用之间没有竞态窗口：`Start` 在 UI 线程上、第一个 `await` 之前就把状态置为 `Connecting`。TCP 的最终仲裁仍是系统 bind。
8. **链路测试保持页面级并使用独立端点。** 切到链路测试页签不再停止任何会话；点击"开始测试"时停止全部运行中的会话并提示数量；切回通信调试时停止在途测试。
9. **TCP 定时发送遵守所选客户端。** 与手动发送共用目标规则：选中了某个客户端就只发给它。目标在点击"定时发送"时确定，目标客户端断开或被踢出后定时发送停止并写一条日志。
10. **事件语义。** `Disconnected` 只表示本会话的链路停止；下挂客户端离开（含踢出）发带端点的 `ClientDisconnected`；服务端向单个客户端发送失败发带端点的 `Lost`，监听未停。
11. **ViewState v2。** 页面状态保存 `Sessions` 与 `SelectedSessionId`，以"`Sessions` 为空"判定旧版扁平存档并迁移为单会话，旧端点同时作为链路测试端点。会话标识随存档恢复，用来恢复选中项。不持久化"全部会话"勾选与合并日志开关。
12. **线程约定。** 接收线程只做 `Log.Enqueue` 与 `Interlocked` 计数；属性、绑定集合与命令通知由页面节拍或 `Dispatcher` 在 UI 线程发布。状态文案只保留最新一条，由 16ms 节拍上屏，不再每条状态一次投递。

## 替代方案

| 方案 | 未采用原因 |
| --- | --- |
| 基类只给 TCP / UDP 用，串口以后再迁 | 过渡期两套实现并存，同一问题要在两处修 |
| 不抽基类，TCP / UDP 各写一份完整实现 | 对串口零风险，但定时发送、会话管理等逻辑三页各一份 |
| 链路测试使用当前会话的端点 | 隐式耦合：切换会话会改变测试目标，而测试页签上看不到会话选择器 |
| 在连接卡上放"+"按钮，或用可编辑 ComboBox 输入 `host:port` | 与串口的下拉添加是两套操作心智；可编辑框还要解析 IPv6 字面量与主机名，模式也没有来源 |
| 运行中保持端点可编辑，提示"下次启动生效" | 显示名会先于真实状态变化，同样误导 |
| UDP 冲突交给系统 bind 报错 | `ReuseAddress` 下同端口双绑定成功，不会报错 |
| 另做一张端口占用登记表 | 不需要：状态置为 `Connecting` 与冲突检查之间没有 `await` |
| TCP 定时发送每拍实时解析所选客户端 | 目标客户端断开后，"只发给它"会变成"发给其余全部客户端"，数据发到别的设备上 |
| 保留会话上限（串口原为 8 路） | 评审结论为全部取消；每一路日志有界，总量随会话数线性增长 |

## 后果

### 行为变化

- 三页的会话选择器、未读徽标、合并日志、"全部会话"发送行为一致；串口取消 8 路上限，"广播"改称"全部会话"。
- TCP / UDP 的日志上限由 100000 行降为分级（20000 / 5000）。
- TCP / UDP 切到链路测试页签不再停通信，改为开始测试时停全部。
- TCP / UDP 的超时提示原来为警告，现在与连接失败一样经会话的出错回调弹出，都显示为错误（与串口一致）。只有当前会话才弹提示。
- UDP 会话的显示名包含发送目标：`0.0.0.0:8080 → 127.0.0.1:9090`、`0.0.0.0:8080 → 组播 239.0.0.1:8080`。设计设想名称只放本地端点、目标放摘要行，但共享的下拉项模板没有摘要行，且同端口上的多个组播会话只看本地端点无法区分。
- 页面离开后会话继续运行，只有在页面上关闭会话才释放端口。

### 已知限制与未验证项

- **P2 的完整界面场景没有执行**（页内环回互发、未读徽标、定时发送定点与目标断开即停、冲突提示、重启恢复、英文界面），**P3 的界面验证全部没有执行**：测试被用户取消。此后后台采集方式也被停用（最小化实例展开下拉时弹出层可见、实例会成为前台窗口），后续界面验证需换方式并先征得用户同意。
- 连续"新建会话"从第二次起无效：已修复（见决策 5 与 `../changelogs.md`）。TCP 在修复后连续新建 4 路通过；UDP 与鼠标、键盘路径没有运行确认。
- 运行时切换语言后的界面刷新未测（后台最小化窗口下 UIA 驱动不了侧栏导航项）。
- `UdpService` 设了 `MulticastLoopback=false`，Windows 上这样的接收端收不到本机发出的组播包。"同端口多个组播会话各收一份"只在数据来自其它主机时成立。属既有行为，是否允许环回待产品决定。
- `ReuseAddress` 的结论来自 Windows 文档与实测，Linux 行为未验证。
- 日志总占用随会话数线性增长，没有做内存测量。
- 切换到别的会话后，下拉项里看不出原来的会话是否还在定时发送。
