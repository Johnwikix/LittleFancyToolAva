# 0013：NVIDIA 光流使用固定新版 FFmpeg 和初始化前设备绑定

日期：2026-10-17

## 背景与约束

RTX 5070 Ti 驱动已暴露 NVIDIA Vulkan 光流能力，但旧 release/9.0 捆绑库没有 fruc_vulkan。仅换库仍会在 hwupload 初始化时失败，原因是设备绑定晚于滤镜初始化。CPU minterpolate 核心没有切片多线程，不应根据低总 CPU 占用判断线程池被限制。

## 决策

- 固定到 FFmpeg `5cb9fcd211` / BtbN `autobuild-2026-10-16-13-04`，Windows/Linux 同步替换六库；保留现有 AutoGen 绑定所需的 ABI 主版本，来源和 SHA-256 随库记录。
- 硬件滤镜先通过 segment API 解析和创建，绑定设备引用后初始化、连接并配置；不再依赖 parse_ptr 之后补设备。VAAPI 走同一设备生命周期，创建失败及时释放，图节点各自持有引用。
- 保留真实帧生成探测、倍率限制、HDR 守卫和明确失败，不根据显卡型号强行启用，不把硬件失败静默回退到 CPU。
- NVIDIA 优先探测线性图像以减少 Windows 回读成本，失败或倍率不全时再验证原布局，保留已验证倍率更多的配置；仍有上传/回读，不宣称零拷贝。布局输出非逐像素一致，差异及适用范围由实测报告记录。
- 保留 CPU 运动补偿质量参数。速度优先仍由实测选择 RIFE GPU，NVIDIA Vulkan 当前保留上传/回读路径。

## 替代方案与后果

继续使用 release/9.0 无法提供缺少的滤镜；只替换 DLL 无法修复设备时序。复制一套独立补帧实现会引入新的原生依赖和资源所有权，当前不采用。主版本一致只能证明 ABI 前提，不能代替全转码、HDR 和 GPU 回归；Windows 当前设备实际生成帧，Linux 只有交叉构建，AMD/VAAPI 缺少设备。该固定 master 构建需要持续锁定和回归，不跟随可变 latest 自动更新。
