# 0020：许可验证临时失败不撤销已确认授权

日期：2026-11-03。

## 背景与约束

ADR 0016 规定任何许可查询失败或超时都立即锁定全部工具，包括已经由 Store 确认过正式许可的会话。实际使用中，Store 服务、网络或账户状态会出现短暂不可用；这类临时故障与“用户未购买”没有关系，却会让已购用户在使用中突然失去全部功能，或在重启后看到验证失败页面。

本次只调整失败后的状态语义，不改变授权来源：仍然只信任 Store 查询与包身份，不引入本地许可文件、离线宽限期或 DEBUG 放行。

## 决策

- 只有 Store 已经明确给出的结论才允许沿用：`FullLicense`、`TrialActive` 或 `LicenseInactive`。
- 上述状态下，后续查询抛异常或等待超时：保留原状态，继续记录警告并等待下一次刷新（30 分钟定时器、`OfflineLicensesChanged`、窗口激活或用户手动刷新）。
- 从未得到过 Store 结论（初始 `Checking`）、包身份不匹配（`PackageIdentityMismatch`）、初始化失败、监控启动失败或已处于 `VerificationFailed`：仍然锁定，不因本次调整放行。
- 试用保留仍受本地约束：UTC 到期时间和本次进程的单调时钟继续生效；查询失败不能延长已确认的试用。
- Store 后续明确返回 `IsActive=false`（非试用、非正式许可）时立即撤权，即使此前是 `FullLicense`；购买返回值仍然不能直接解锁，购买后必须重新查询。
- 保留仅限当前进程内存。应用重启后必须重新向 Store 验证，不新增磁盘缓存或本地授权文件。
- UI 继续直接显示保留的状态；临时失败只体现在日志中，不把已购用户误报为“验证失败”或“需要购买”。

## 替代方案

- 持久化最后一次有效许可：可跨重启离线放行，但会引入可被复制或回拨的信任来源，本次不采用。
- 固定宽限期（例如 24 小时）后锁定：更保守，但需要新增状态、持久化时间戳和 UI 说明；当前没有产品要求，保留为后续可选项。
- 仅增加启动重试而不保留状态：不能解决运行中 Store 临时故障导致的撤权，且会延长冷启动锁定页停留时间。
- 继续任何失败都锁定：实现最简单，但违背本次要解决的已购用户临时故障问题。

## 后果与已知限制

- 已购用户和试用用户在同一进程内不会因 Store 临时故障失去功能；Store 恢复后正常刷新。
- 若商品被退款或撤权，而 Store 查询持续失败，应用在本次进程内可能继续放行；下一次成功查询或重启会重新判定。这是保留策略的明确代价。
- 冷启动时若从未成功查询且 Store 不可用，仍然锁定；用户可在窗口激活时自动重试或手动点击重新验证。
- 包身份仍是最前置的硬边界：错误身份不会查询、不会购买、不会放行。

## 验证

`FancyTool/_tools/LicenseSmokeTest` 已覆盖：

- 首次查询失败、初始化失败、监控启动失败、包身份不匹配仍锁定；
- 正式许可后查询失败/超时保留授权，迟到结果不生效；
- 试用失败保留，但本地到期后立即锁定；
- Store 明确返回非活跃时撤销已确认的正式许可；
- 购买取消/失败不解锁，购买后重新查询。

原始结果保存在 `.qa/license-transient-2026-11-03/`。
