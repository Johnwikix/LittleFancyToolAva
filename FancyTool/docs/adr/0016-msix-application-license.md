# 0016：MSIX 全应用试用与正式许可门控

日期：2026-10-31。

> 后续修复：实际 Store 商品包身份、已购电脑误锁及设置页授权状态见 [ADR 0017](0017-store-package-identity.md)。严格门控不变，身份错误和验证失败不再一律提示用户购买。

## 背景与约束

MSIX 发行需要在试用到期后禁用全部工具并提示购买；非 MSIX Windows / Linux 发布始终完全解锁。基线 `ffmpeg` 分支此前没有应用内许可门控。

Store 查询、购买窗口 HWND 关联、离线许可事件和在途刷新补查参照已投入使用的 `G:\SoftwareProject\winui\music_player\Services\LicenseService.cs`。本项目采用更严格的产品策略，不保留该程序的部分功能免费、非 Store 签名放行、首次查询失败放行、后续失败沿用旧权限或 DEBUG 本地覆盖规则。

## 决策

### 渠道与唯一状态源

`FancyToolMsixBuild=true` 定义 `FANCYTOOL_MSIX`。只有 `WINDOWS && FANCYTOOL_MSIX` 编译真实 `WindowsStoreLicenseBackend`；误将 MSIX 标记用于非 Windows 目标会明确编译失败，不静默变成免费渠道。普通构建不编译 Store 后端，默认许可立即为 `Unrestricted`，不创建授权定时器或调用 Store API。

`ILicenseService` 是唯一授权状态源，没有持久化许可、环境变量开关、DEBUG 覆盖、签名类型例外或“未知即放行”。`_tools` 的可控 Store / 时间边界只在独立测试宿主使用；主程序不编译 `_tools`。

| 情况 | 全部工具 | 恢复方式 |
| --- | --- | --- |
| 非 MSIX 发布 | 全部开放 | 不需要授权操作 |
| MSIX 正在初查 | 不创建、不启动 | 等待验证 |
| Store 返回有效正式许可 | 全部开放 | — |
| Store 返回有效试用，且有未来的到期时间 | 全部开放 | 到期前购买 |
| 试用到期 / 缺失到期时间 / 许可非活跃 | 全部锁定 | 购买后重新验证 |
| 无包身份、Store 初始化失败、初查或后续查询失败 / 超时 | 全部锁定 | 检查 Store 登录、网络与包身份后重试 |
| 无法启动授权监控 | 全部锁定 | 重新启动应用 |

试用时长来自 Store，不新增本地试用计时或宽限期。有效试用还要通过 UTC 到期时间和本次进程的单调时钟两项检查；重复查询相同截止时间不重置单调时钟。到期每秒检查，权限 getter 与导航入口也即时检查，不等到下一次 Store 查询才拒绝。

### 初始化、购买与并发

- 主窗口建立 HWND 后初始化 Store；初查通过前只创建主窗口、授权 ViewModel 与偏好/状态服务，不构造工具 ViewModel，不启动模型预热、FFmpeg 探测或通信服务。
- 许可状态与绑定通知在 Avalonia UI 线程维护；窗口激活、Store 离线许可事件和 30 分钟定时器触发刷新。在途请求单飞并补查，避免购买后的新许可被旧查询覆盖。
- 单次查询等待上限为 20 秒；超时立即锁定。取消等待不代表 WinRT 调用已经停止，因此旧调用结束前不叠加查询，旧结果作废，恢复需要一次新查询。
- 购买串行合并；成功、取消或失败后都重新查询，购买返回值本身不能解锁。优先从当前应用查询 StoreId，失败时打开本项目 `9P543GHQQKVK` 商店页；不使用参考播放器的商品编号。
- 锁定页保留购买、重新验证和窗口关闭。购买提示使用 FluentAvalonia `FAContentDialog`；关闭或 Esc 不会打开工具。中英文资源同名，语言变化刷新代码文本。
- 锁定启动未注册任何页面，退出时不保存空的 ViewState，避免清除已有页面偏好。

### 运行中撤权

只盖住 UI 无法停止已在执行的通信、下载、批处理与进程内 FFmpeg / GPU 推理。本项目在已经启动工具后失去授权时，禁用并隐藏原窗口，尝试保存页面状态，然后启动同一可执行文件重新核验，最后结束旧进程。

`LicenseSessionRestarter` 用 `finally` 保证终止：隐藏、保存或启动新进程任一失败都不能跳过退出。特殊撤权路径不在 UI 线程同步 Dispose 正在使用的原生会话，由 OS 回收整个进程的句柄和线程，避免仅取消等待后后台任务继续执行。常规退出流程保持原样。新进程没有跳过授权的参数或本地标记。

这一策略会中断在途操作，尚未完成的输出可能不完整；若新进程启动失败，旧会话仍然结束，需要手动重新打开应用。它是收紧全功能授权的明确后果，不承诺完成或回滚已经开始的原生写入。

## 替代方案

- 只锁 AI 或禁用导航按钮：不满足全功能门控，也挡不住后台工作。
- 复制参考程序的失败放行或 DEBUG 覆盖：不符合本项目收紧授权的要求。
- 给每个现有及未来工具单独添加取消与许可守卫：容易遗漏入口；原生任务取消完成之前仍可能继续运行。本次采用统一的工具创建边界与进程撤权边界，原始处理管线不改写。
- 使用本地缓存许可或本地计时延长离线使用：会引入新的信任来源，本次不采用。Store 自身能返回有效离线许可时仍可开放；Store API 失败则锁定。
